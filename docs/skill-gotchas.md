# Skill gotchas

One line per gotcha: the reference file it belongs in, then the fact.

- scripts/fetch_emu.py (setup.md): `fetch_emu.py gba-bios` fails with HTTP 404 (retrobios path `bios/Nintendo/Game%20Boy%20Advance/gba_bios.bin` moved, 2026-11-14); copied a SHA-1-matching gba_bios.bin from a sibling project instead.
- emulator-qa.md: the stock `watch.lua` logs one line per distinct PC, so a routine that walks a table (font blitter) shows a single address; `tools/lua/readmap.lua` logs per (pc, 256-byte page) and found the font in one run.
- platform-gba.md: Bandai GBA games may store text as 16-bit font-cell indices in Shift-JIS cell order (code = SJIS cell + 1, with a shift after lead 0x84): relsearch `--width 2` order `jis` finds it, `jp_left.py --sjis` does not.
- references/graphics.md §Survey: a plain LZ77 header scan over a GBA ROM gives ~1% header-shaped false hits in code; keeping only blocks that sit back to back with a neighbour or have a ROM pointer removed them (60 of 6069). Blocks rendered as 4bpp that show vertical stripes are u16 tables/tilemaps: "odd bytes have < 35% the distinct values of even bytes" filtered ~1000 of them (`tools/gfxsweep.py classify`).
- references/emulator-qa.md §Visual QA: in an Orca worker (no nested subagents), `codex exec -s read-only -i page.png ...` works as the read-only sheet reviewer (`tools/sweep_review.py`); calibrate it on one page with known Japanese first.
- references/emulator-qa.md §Debug tool: for an event-script engine, the fastest warp is to write a few opcodes (load map, place hero, call map init, fade in, call scene script) into spare RAM and hand that pointer to the engine's own "run event" slot (here `GS+0x1E18` + field mode 2): no flag RE needed, and any scene script runs directly. Find the opcode table first (xref one handler), then read door scripts for the map-change pattern.
- references/emulator-qa.md §emu.py: GBA games often keep their state objects in EWRAM (0x02xxxxxx) behind IWRAM pointers; a Lua range check that only accepts IWRAM pointers silently disables the whole warp (cost one debug cycle).
- references/pipeline.md §Recon 2 / emulator-qa.md §Hooks: a Lua read-hook trap test cannot see DMA reads: this game's 8x8 font is DMA'd tile by tile from `literal + code*32`, and the literal (`0x082FFFE0`, base - 32) pointed into a "free" FF run. Check code literals pointing into a candidate range as well as runtime reads.
- references/pipeline.md §Marker: a digraph scheme can serve two fonts at once when both index glyphs by the same code (here 12x12 cell = base + code*24, 8x8 tile = base + code*32): relocate both fonts and append pair glyphs at the same codes, so names drawn in both fonts need one encoding.
- references/pipeline.md §Extract: event-script sites came out duplicated (same pointer offset listed 2-4 times when scripts share code); a repointer must dedupe them or romdiff reports overlapping writes.
- references/pipeline.md §Extract: a whole-ROM byte-pattern scan for pointer opcodes (`7A <slot> <ptr>`) produced false "tail pointers" from graphics data (0xC86CCA); walking decoded scripts gave none. Script discovery needed three extra seed sources beyond the map triggers: aligned pointer tables outside the event region, scripts stored back to back after an FF (accept only if they decode to FF and hold a text/script pointer), and quest records with tag bytes before each pointer.
- references/emulator-qa.md §Hooks: MesenCE 2.2.1 GBA: `emu.addMemoryCallback` read callbacks on EWRAM (0x0200xxxx) never fired (ROM reads and EWRAM writes do), whether registered at start or from on_frame; find RAM structures by write hooks or dumps instead.
- references/pipeline.md §Marker: a fixed-size table field (no terminator when full) can be read by one screen up to the field size and by another until 0000: the marker build must fill only to size-2 unless the JP itself fills such fields, or the second reader runs into the next record (here the PLACE banner).
- references/emulator-qa.md §Debug tool: state grants are easiest as injected event opcodes (give item / add money) in a spare-EWRAM script the warp script calls, found by xref from the shop's buy routine (money getter + add-item), plus raw POKEs into the save object for EXP and book bits; GOD/KILL by holding actor HP in the battle actor list.
- references/emulator-qa.md §Hooks: correction to the EWRAM-read line above: `probes/watch.lua` with `WATCH_MODE='read'` on EWRAM (0x02003BAC-0x02006F00) did log reads in MesenCE 2.2.1 (session 3, from a `--state-in` start); the earlier miss was probably the registration path, not EWRAM itself.
- references/emulator-qa.md §Agent playtest: `play.py` shots are upscaled x2 (482x322 for GBA), so `sheet.py --crop` on them takes doubled coordinates; `emu.py --state` is ambiguous (use `--state-in`), and `--route-str` steps are "FRAMES BUTTONS" ("6 a;150 -"), not warp.lua's "6_a".
- references/emulator-qa.md §Debug tool: a grant that injects a game opcode with ROM pointers (here op 6F quest + client string) must copy the op bytes from the running ROM (`OPS=@offset+len` in warp.lua), not hard-code them: the build relocates the string and a hard-coded pointer shows the stale Japanese (or a mix) on stress builds.
- references/pipeline.md §Width gate: to settle "is this table field ever drawn?", pair the textcover read probe over many scenes with a static check of every code literal pointing at the table and the field offsets the code reads after it (here areas/wtypes refs touched only numeric fields): two independent kinds of evidence before marking a field unused.
- references/emulator-qa.md §emu.py: MesenCE keeps battery saves in tools/mesen/Saves/<rom stem>.sav across runs; a scene that saves (suspend/save) turns every later cold boot of the same ROM name into a continue title and warps stall there. warpall.py now deletes it before and after a run; emu.py could run each Mesen boot with a fresh save dir unless --sav is given.
- references/pipeline.md §Width gate: a ruler far longer than a fixed UI window (60 letters in a 6-letter window) wraps over the rows below and garbles them; give short windows the JP width + 4..6 (A-Z) and tag long rulers with the string id (tools/qaruler.py), else two boxes with the same ruler can't be told apart.
- assets/batches.py (references/translation.md): index()/check/merge keyed entries by id, so a table whose records share one id per slot (tbl_voices: 11 shouts per id) collapsed to the last row on merge and the no-arg lint skipped 240 entries; key by id@addr when an id repeats and resolve batch rows by (id, JP).
- scripts/lua/probes/textcover.lua (references/emulator-qa.md §Text coverage): when relocated text shares a free-space range with relocated fonts, exclude the font span from RANGES, or every glyph read is logged; build/strings.tsv should hold ROM offsets and textcover.py run with --mask 0x1FFFFFF on GBA (CPU reads come as 08xxxxxx).
- assets/batches.py wrap_line (references/translation.md): greedy wrap left 412 one-word widows; balanced wrap (greedy line count at the narrowest width that keeps it) plus a lint for last lines under 6 letters fixed them mechanically. wrap also stripped leading blanks of hand-indented draw text (en.strip()).
- visual QA without nested workers (Orca): tools/vqa.py sends each qa_gate chunk to codex exec -s read-only with EN + original shots attached and takes the final message (-o) as the verdict file; worked first try.
- references/graphics.md (redraws in place): a screen's ROM tilemap is not always what the game draws: the title-menu strips are laid out by code from the tile block (map ignored, palette swapped for the highlight), so re-tiling the map (dedupe/relayout) put stray tiles on screen; such strips must be rewritten tile-for-tile. Check a re-tiled screen in a cold-boot shot, not only in a map render.
- references/graphics.md (tile budgets): when a redrawn label needs more tiles than the old one frees, dedupe the whole screen first (exact + flipped repeats) and choose label x by tile count (cell alignment moves the need by 2-5 tiles); look at VRAM after the block in a PPU dump before growing a block.
